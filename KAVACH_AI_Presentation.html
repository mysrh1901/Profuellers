Custom LLM

🧠 KAVACH Compliance LLM — Our Own Model

Fine-Tuning Pipeline — How We Built It

Step 1: Collect training pairs
Each example = "here's code" → "here's the compliance violation"
Source: past audit findings, Checkmarx reports, SOX evidence, MSA clauses
Volume: 500-1000 pairs (started with 15, expanding)

Step 2: Freeze model, train small adapters (QLoRA)
Base model: Llama 3.2 (1.2B params) — frozen at 99.7%
We add 4M trainable adapter parameters on top
Train only adapters on our data (~2-6 hours, one GPU, ~$50-100)

Step 3: Merge, export, deploy
Merge adapters back into base → export to Ollama format
Result: kavach-compliance-v1 — runs on our infra
No client code sent to external APIs (stays within our network)

Knowledge Graph + GraphRAG

🕸️ Compliance Knowledge Graph with Graph RAG

How GraphRAG Works in KAVACH

1. Compliance Knowledge Graph
We model all regulations, controls, systems, and clients as a connected graph. Each entity is a node, and relationships (violates, requires, triggers, penalizes) are edges. This captures how compliance domains depend on each other.

2. Causal Path Traversal
When an event occurs (e.g., SQL injection detected), the engine traverses the graph to discover all impacted regulations and downstream consequences — for example: SQL injection → violates PCI-DSS 6.5 → triggers MSA §7.2 SLA (48h) → exposes $50K penalty → requires SOX disclosure.

3. Retrieval-Augmented Generation (RAG)
The retrieved causal paths are passed as context to our LLM. Instead of the model reasoning from general knowledge alone, it receives the specific compliance relationships relevant to this event — enabling precise, regulation-aware analysis.

4. Multi-Domain Impact Output
Result: a structured response showing every affected domain, specific regulation references, severity levels, and required actions — all within 2 seconds of the triggering event.
